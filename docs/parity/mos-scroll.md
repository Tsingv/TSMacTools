# Mos scrolling parity notes

`references/Mos` is a read-only conceptual and behavioral reference. TSMacTools does not copy Mos's runtime objects or configuration model: the local implementation keeps typed settings and a deterministic value-type engine/session in `MacToolsCore`, while the independently testable `MacToolsMacOS` target owns macOS event and display handles.

`Tools/check_mos_provenance.py` supplies a reproducible narrow guard against accidental block transplantation. It compares the four local Mos-informed implementation files against Swift/Objective-C sources under `references/Mos/Mos` after removing line comments and whitespace, and fails on an exact normalized match of four or more consecutive source lines. This heuristic complements architecture/code review; it is not a general similarity detector or legal conclusion.

## Local ownership

- `Sources/MacToolsCore/SmoothScrollModels.swift`: presets, bounded tuning values, the complete tracking/momentum phase state machine, smoothing state, generation/TTL/PID session state, and event-tap restart limiting. This layer has no Accessibility or display dependency.
- `Sources/MacToolsMacOS/SmoothScrollController.swift`: the injected controller plus live scroll/mouse event tap, source and target classification, serialized synthetic-event posting, display clock, screen-change rebuild, and thread-safe handle cleanup. Tests substitute fakes without changing controller policy.
- `Sources/MacToolsApp/SmoothScrollController.swift`: a thin typealias that exposes the `MacToolsMacOS` implementation to the App target.
- `Sources/MacToolsApp/SettingsWindowController.swift`: settings presentation and field-preserving edits for common automation/translation fields, hotkeys, presets, axes, direction, trackpad bypass, and custom tuning; advanced JSONC-only fields remain explicitly discoverable.
- `Sources/MacToolsApp/AppDelegate.swift`: long-lived window-switcher, hotkey, and scroll controllers receive targeted configuration updates instead of rebuilding unrelated working handles on every reload.

The preset names are TSMacTools concepts, not Mos or Smooze Pro compatibility claims. `precise`, `balanced`, `fluid`, and `glide` select increasingly long and fast local curves; `custom` exposes `step`, `speed`, `duration`, `acceleration`, and `deadZone`.

## Regression coverage audit

| Regression concern learned from Mos | Local behavior and owner | Automated evidence | Permission/device verification |
| --- | --- | --- | --- |
| Event tap disabled by timeout or user input | The callback resets the active session and attempts recovery only while Accessibility remains trusted. Revocation removes the tap instead of re-enabling a zombie; restoration creates a fresh tap. `EventTapRestartLimiter` permits at most three attempts per 60 seconds. | `testEventTapRestartLimiterThrottlesAndRecovers` and `testPermissionRevocationRecoveryIsBounded` cover limiter policy, removal while untrusted, one fresh restore, and bounded repeated failure. | Revoke Accessibility while physically scrolling and confirm input is no longer intercepted; restore it and confirm smooth scrolling resumes without a rapid restart loop. |
| Display clock cannot be created, started, has not produced its first callback for the current run, or becomes unavailable | A raw, non-smoothed event remains in the system path until the current display-link run has both started and delivered a real frame; a callback from an earlier run cannot authorize consuming input after restart. Configured reversal changes line, point, and fixed-point fields independently. An unavailable callback clears the prepared tail before rebuild. | `testDisplayPrepareFailureLeavesTapUninstalledAndEventUntouched`, `testDisplayStartFailurePassesThroughOriginalFields`, `testDisplayStartWithoutFirstCallbackPassesThroughUntilReady`, `testIdleStopRequiresCurrentRunCallbackBeforeConsumingNextGesture`, and `testDisplayUnavailableDropsPendingTail` cover controller policy. | Real CoreVideo create/start/stall behavior remains a device/OS integration check; the live display-driver deinit test is skipped when the test host has no active CoreVideo display. |
| Display topology changes | `NSApplication.didChangeScreenParametersNotification` coalesces changes for 500 ms, resets current motion, then recreates the reusable display link only while scrolling is enabled. | `testScreenChangeRebuildIsDebouncedAndCancelledByShutdown` and `testDisabledControllerIgnoresPendingAndLaterScreenChanges` cover coalescing, shutdown, pending-disable cancellation, and disabled suppression. | Connect/disconnect a display or change refresh rate while scrolling; confirm the real CoreVideo link resumes and no stale tail crosses the change. |
| Event/display handles outlive their owner or synchronous display stop waits on controller work | CoreVideo output callbacks only mark current-run readiness and coalesce timestamps onto a serial delivery queue before entering the controller. `CVDisplayLinkStop` therefore cannot wait on controller work that is blocked by the operation lock held during mouse-down cancellation, idle stop, reload, or teardown. Display-run generations reject queued work after stop/restart. Shutdown and deinit remain idempotent from the owning main thread or a background final release. | `testLiveDisplayStopDoesNotWaitForControllerFrameWork` stalls real controller-frame work and proves live display stop still returns. `testConcurrentFrameCallbacksAreSerializedAndShutdownRejectsLateFrames`, `testLiveDriversCanDeinitializeOffMain`, `testBackgroundDeinitCancelsHealthAndIdleTasks`, and `testPreparedLiveDisplayDriverCanInvalidateOffMain` cover concurrent/late frames, background last-release, task cancellation, and live invalidation. | Repeatedly scroll, click into another application during the tail, reload/disable, and terminate under Instruments; confirm the app remains responsive and real tap, run-loop-source, display-link, timer, observer, queue, and registry counts return to baseline. |
| Configuration reload recreates expensive handles or adds latency | App reload retains all three controllers. Scroll applies typed state to existing driver objects; hotkeys re-register only when the binding array changes; an enabled window switcher updates configuration without recreating its CGEvent tap. | `testConfigurationApplyReusesDriversAndOnlyReinstallsTapAfterDisable` proves scroll driver/tap reuse. The App/controller-specific branches are code-reviewed but do not yet have injectable Carbon/window-tap counters. | Change scroll, provider, hotkey, and window-only fields separately under Instruments. Confirm unrelated tap/registration counts stay stable and the first input has no duplicate-setup delay. |
| The display hot path allocates an event per frame or trusts stale readiness after idle restart | Each physical input creates one pixel-unit template and every display frame mutates that same `CGEvent`. Normal idle stop retains the prepared display-link handle but clears readiness; the next run remains fail-open until its own first callback. Only topology change, failure recovery, or invalidation rebuilds the handle. | `testDisplayFramesReuseOneSyntheticEventTemplate` proves pointer identity across frames. `testIdleStopRequiresCurrentRunCallbackBeforeConsumingNextGesture` proves stale and stopped-run callbacks cannot authorize consumption while prepare/recreate counts remain unchanged. | Record allocations and first-input latency with Instruments while alternating isolated notches and long glides; confirm no per-frame `CGEvent` allocation, no handle growth, and raw pass-through instead of a dead notch when restart stalls. |
| Old or concurrent callbacks post a stale/reordered tail after reset/reload | Every physical input/reset advances a generation, templates expire after `max(2 seconds, duration + 1 second)`, and one recursive operation lock serializes frame preparation/posting with reset and teardown. | Session tests cover generation/TTL; `testConcurrentFrameCallbacksAreSerializedAndShutdownRejectsLateFrames`, `testExpiredTailDoesNotPost`, and the late-callback shutdown test cover controller interleavings. | Start a long glide, reload or disable mid-tail, and confirm no movement reaches the former target; this remains a real display-callback timing check. |
| Tracking/momentum phases are malformed or a new gesture continues old momentum | The engine emits tracking begin/change/end followed by momentum begin/change/end. Input during momentum first emits a zero-delta momentum end, then starts new tracking without consuming the new delta. | `testPhaseStateMachineEmitsEveryTrackingAndMomentumBoundaryInOrder` and `testNewInputEndsMomentumBeforeRestartingTrackingWithoutLosingDelta` assert exact collapsed phase order, monotonic convergence, and delta conservation. | Verify phase-sensitive applications and rapid direction changes with a physical wheel; confirm no stuck gesture or tug-of-war. |
| Direction changes fight old momentum | Each engine axis drops an opposing remainder before accepting the new delta. Direction reversal is independently applied per axis before smoothing. Owner: `SmoothScrollEngine` and `SmoothScrollController`. | `testDirectionChangeDropsOpposingTail` covers removal of an opposing tail. | With `reverseVertical` and `reverseHorizontal` tested separately, reverse the wheel direction rapidly and confirm there is no tug-of-war or movement in the pre-change direction. |
| Mechanical line-unit input is consumed but the synthetic event does not scroll, or one notch is repeated on every animation frame | Each physical wheel input creates one reusable pixel-unit template. Point/fixed movement is animated, while original line distance is accumulated and emitted only on the next frame so line-oriented consumers receive usable output without multiplying a notch across the tail. | `testLineUnitWheelPostsUsableLineDeltaInFirstSyntheticFrame` starts with a line-only physical event, asserts precise nonzero AppKit movement and the tracking-begin phase, then proves the whole synthetic sequence preserves exactly one line of total compatibility output. | Verify detented and high-resolution mice in Finder, browsers, editors, and any application that previously ignored point-only synthetic output. |
| Trackpad gestures or driver-generated wheels are misclassified | With `excludeTrackpad`, native phase/scroll-count gestures bypass smoothing, but source metadata identifies Logitech Options wheel events as mouse input. Classification uses characteristics and a local normalized identity-fragment matcher, not delta magnitude; its one-process cache is dropped when the source application terminates so PID reuse cannot retain stale identity. | `testTrackpadClassificationUsesPhasesNotDeltaSize`, `testRemoteContinuousBypassesAndLogitechWheelOverridesScrollCount`, and `testSourceIdentityClassifierUsesIndependentFragmentsAndLogitechPrecedence` cover native classification, bundle variants, system-process paths, unrelated applications, and the Logitech override without global device-state leakage. | Compare trackpad, Magic Mouse, detented/high-resolution mice, Logitech Options, PID reuse after a driver/client restart, and other third-party drivers against the disabled feature. |
| Mixed horizontal/vertical input loses or duplicates the unsmoothed axis | Each axis is selected independently. The original event continues once with only the smoothed axis zeroed; the synthetic template zeros line, point, and fixed representations for the passthrough axis. | `testMixedAxisInputPassesUnsmoothedAxisExactlyOnce` plus `testMixedAxisSyntheticEventZerosEveryUnsmoothedRepresentation` inspect both the original event and every synthetic-axis representation. | Verify diagonal input in applications that consume different CGEvent fields, especially third-party mouse drivers. |
| Synthetic tail is ignored or follows the wrong target | The source target PID is captured in `SmoothScrollSession` for generation changes and older-system direct delivery. On macOS 26, marked frames use the session tap plus the copied physical location because observed direct-to-PID wheel frames were ignored by WeChat; the marker prevents recursion. A new target invalidates the old generation and terminal idle clears routing. | PID-switch/session tests plus `testUnknownPIDDoesNotReuseCompletedSessionTarget` cover generation, stale-plan rejection, terminal clearing, and zero-PID fallback; bounded Debug routing logs provide physical-device evidence. | On macOS 26, verify representative AppKit, Chromium, Electron, and WeChat targets under the pointer; on older systems, confirm direct `postToPid` delivery stays with the captured application. |
| Already-smoothed remote input is smoothed again | Continuous events from remote-control identities recognized by normalized bundle/executable fragments bypass the local engine, while local and Logitech wheel sources remain eligible. | `testRemoteContinuousBypassesAndLogitechWheelOverridesScrollCount` injects both source classes and proves the display driver does not start for remote continuous input; `testSourceIdentityClassifierUsesIndependentFragmentsAndLogitechPrecedence` covers representative identity variants. | Verify Screen Sharing plus representative third-party remote clients; unknown clients may need classifier expansion. |
| Synthetic events recursively re-enter the engine | Every local synthetic event carries a private marker checked before classification or driver start. | `testSyntheticMarkerPassesThroughWithoutReenteringSmoothing` proves no frame start or post occurs. | Watch CPU and scroll distance during long glides; confirm one physical gesture is not amplified. |
| Launchpad/Dock targets or a click retain an unwanted tail | A target-bypass seam passes legacy pre-macOS 26 Dock paging through unchanged, and mouse-down invalidates the current generation and stops pending motion. | `testLegacyDockBypassAndMouseDownCancelTail` covers both policies without requiring Launchpad or Accessibility. | On a supported pre-macOS 26 machine, verify Launchpad/Dock paging; on current macOS, click during a glide and confirm the page stops immediately. |

## Existing automatic suite

`Tests/MacToolsCoreTests/SmoothScrollEngineTests.swift` proves presets, bounds, convergence, complete phase order/interruption, opposing-tail removal, burst separation, independent axes, trackpad classification, restart throttling, and generation/TTL/PID routing. `Tests/MacToolsMacOSTests/SmoothScrollControllerTests.swift` proves adapter failure/unavailable fallback, permission limiting, screen debounce/disabled suppression, concurrent and late callbacks, background teardown, PID routing, TTL, source classification, recursion prevention, mixed-axis fields, legacy Dock policy, and mouse-down cancellation. `Tests/MacToolsCoreTests/UserConfigurationStoreTests.swift` proves default/legacy scroll behavior plus comment-, unknown-field-, and concurrent-edit-preserving Settings mutations.

These tests deliberately replace Accessibility, event-tap, CoreVideo, clock, scheduler, and post operations with deterministic fakes. They prove controller policy without prompting for permissions; the last column retains the real OS/device evidence required before a release claim.

## Known audit gaps

- Real Accessibility revocation/restoration and real CoreVideo create/start/stall behavior cannot be fully proven by fake adapters; the current full suite skips the prepared-live-display invalidation test when the XCTest host has no active CoreVideo display.
- Physical detented wheels, high-resolution devices, Magic Mouse/trackpad bypass, and third-party drivers still require hardware classification checks.
- Instruments verification is still required for repeated reload/enable/disable handle counts and first-input latency.
- The Debug app has rendered the three standard Settings pages plus compact 760 x 540 Hotkeys/Scrolling variants in light and dark appearance through `--render-settings-previews`, with owned layout ambiguity assertions. Hotkey capture/cancel, field editing, scrolling/resizing, and actual status-menu presentation still require interactive verification.
